# 跨行业信源平台工作系统（v1.1）

适用对象：建立某一行业、地区、产品、机构、项目或事件的**可追溯查询平台**。这是一套研究、建模、采集、审核、发布和持续更新的交付协议，不是“通用爬虫”或“把搜索结果变成数据库”的捷径。启用时复制[统一模板](source-platform-templates.md)，另开一个行业研究任务；不要直接复制教培的资质和对象定义。

## 零、三块底座与可替换边界

目标是**换领域时复用工作方法和可信数据链**，不是承诺只改一行信源配置就能上线。把三个维度分开管理：

| 维度 | 可以长期复用 | 切换领域／地区时必须重新核定 |
| --- | --- | --- |
| 地理底座 | 带版本的地区代码、名称、层级、父子关系、历史别名和有效期；地区任务索引 | 适用司法辖区、监管口径、跨地区对象、功能区映射；某来源声称的覆盖范围 |
| 技术流水线 | 有界请求账本、同站互斥、不可变原件与哈希、行定位、字段证据、复核队列、发布闸门和回滚 | 站点实际访问条件、解析器、增量规则、身份校验、抽取率阈值与错误语义 |
| 领域目录 | 来源登记、状态、权利证据、调查任务及更新责任的结构 | 领域对象、主管机关、字段定义、来源优先级、证明边界、公开页面任务 |

一次交付按“需求与主张 → 地区／类别及来源调查 → 获准的有限采集 → 原件和字段证据 → 关联复核 → 审批后的产品投影”流转。每段输出带 ID、版本、状态、错误和责任人；下一段不能从上一段的“技术成功”推导“事实已核实”或“有权公开”。这里的统一接口是**证据收据**，不是用请求级 confidence 取代逐字段证据。

建议的最小接口：来源适配器接收 source_id、地区任务、批次预算与上次收据，返回 RawArtifact（原始字节或文件、请求事实）及 SourceObservation（原样字段、来源行定位）；离线领域映射器把观察转成候选对象和 FieldEvidence；人工复核服务只决定关联与字段主张；公开投影器只读取逐字段已批准的证据。适配器允许因网页、附件、授权 API 不同而写来源专属代码，不预造一个靠配置就能解析所有站点的“万能采集器”。

地理数据应先确定范围（例如中国大陆与港澳台的不同适用制度）、权威版本日期和许可条件，再导入固定快照；保留原始地区标注、标准代码、匹配依据与匹配状态。地址地理编码只能生成候选地区，不能把解析结果当成原始公告的行政归属。行政区变更通过有效起止日期和映射表留痕，不覆盖旧公告中的旧代码；对象可能跨地区、线上服务或地址未知，因此业务表的 region_code 可空，关系也可多对多。线上生产库须遵守项目实际部署约束，不能把本地 SQLite 文件直接当成 Cloudflare Edge 的生产数据库。

## 一、从用户任务反推要证明的主张

先写一句“用户在什么场景，需要判断什么”，再列平台拟展示的每一项**主张**。例如“某单位在某公告截止日被列入名单”“某地点有某主管部门发出的许可证”“某主体在某日登记存续”是三种不同主张；不能被压成“该机构合法在营”。页面上的每一个状态词必须能回到一条有适用对象和时间的证据。

接到新方向时先填六组输入：①目标用户与查询任务；②地域和行政层级；③待查询的真实对象及类别；④必须展示的字段与用户可能采取的决定；⑤内部研究、公开展示、商用、API 或再分发的用途；⑥时间、预算、更新期望。缺少决定方向的答案才问 1—3 个问题；其余标为假设并继续做桌面研究。

默认按三个速度层次交付，不把进度层级混同质量：

| 层次 | 应交付 | 不能宣称 |
|---|---|---|
| 方案速写 | 对象草图、用户任务、来源候选、缺口、预算和 1—3 个优先核验点 | 来源已可用、可批量获取、已有覆盖率 |
| 证据调研 | 权威地区/类别树、原件 URL、至少一行样本、访问/条款结果、四项采集判断、试点比较 | 单个样本等于整地区完整覆盖或当前有效状态 |
| 可运行试点 | 来源专属适配、原件/账本/收据、字段证据、人工复核、受控投影及验收结果 | 未授权公开、未经核验的实体合并、全国上线 |

方案速写可在一次工作会话内形成；后两层耗时由来源访问、附件质量、授权及人工复核决定，不预设固定完成日。

## 二、先建对象和“可主张事实”表

将**登记主体、受监管的业务对象、经营场所、许可/备案、品牌、产品/服务、官方名单行**分开；某行业可能缺其中一些，也可能有独有对象。每个对象写明主键、自然标识是否可靠、时间有效性、上级/下级关系和同名风险。不能沿用其他行业对“许可证”“在营”“校区”“备案”的解释。

用“来源类型 → 能证明的主张 → 不能证明的主张”约束字段。例如登记信息通常能证明登记主体某时点的名称/状态，不能直接证明某场所正在提供服务；商业目录是发现线索，未必能证明许可；监管名单只证明其标注的对象、范围和名单日期，不自动证明今天仍有效。字段优先级要按**具体字段与主管机关**确定，不设通用的“官方永远优先”总分。

基础关系按证据建立：主体和场所、品牌和主体、证件和业务对象可能随时间变化，必要时多对多；来源行永不因同名或同号而丢弃。自动匹配只写候选关联、理由和反证；公开的“已确认关联”须有强标识或人工复核记录。名称变更、经营者变更、撤销/停办、同址多对象与旧证换证保留完整时间轴。

## 三、调查范围与来源注册

先确定**地区树、业务类别树和版本**，再建立地区×类别任务。行政区划、监管辖区与平台自定义商圈不必相同；不设区城市、功能区、跨省品牌和全国公告须单独标适用范围。上级名单只可证明公告自己声称的覆盖范围，不能把每个下级任务自动标为已覆盖。

地区任务状态：未调查、已找到、已核验、受阻、已检索未发现、经限定范围确认无适用来源。最后一项必须保存检索范围/日期和反证方法；未知保持 null，不写 0。**来源已核验**指某一原件的标题、发布者、日期、样本行与访问证据完整；**地区已覆盖**另需核公告适用范围、各下级是否存在缺口和持续更新路径。

来源发现按优先级找：主管/登记机关原始公告或开放文件 → 依法授权的数据接口/开放数据集 → 行业协会/运营主体一方资料 → 商业目录。这个顺序只是调查顺序，字段权威性仍逐字段判定。每份具体公告或数据集登记准确原件 URL、发布者、发布时间、截至日、区域、类别、逐条字段、可见记录数、更新线索、样本定位、使用条件与核验时间；搜索摘要只算线索。

每个来源必须分别回答四问，不能合并成“能抓”：

1. 公众能否查询单个对象，是否有登录/验证码？
2. 是否存在公开、可解析的 HTML/CSV/XLSX/PDF/API 原件，具体字段与格式是什么？
3. 对计划的**自动访问频率**及计划的**内容再利用方式**，各有什么权利或限制证据？
4. 是否有稳定原始 ID、发布日期/截至日、撤回/更新线索，能否长期对比？

四项可分别为“是／否／未知／受阻”，并记录证据。HTTP 200、浏览器可查、robots 未声明、政府主动公开，彼此都不自动构成下一项的许可。对版权、数据库编排、个人信息和合同条款应由具体事实与使用场景判断；本项目对面向客户的目录可采用更保守的逐源审批门槛，但不把它伪装成对所有公开事实的普遍法律结论。

## 四、证据链和最小数据模型

~~~mermaid
flowchart LR
  S[Source 来源定义] --> R[RawArtifact 不可变原件]
  R --> O[SourceObservation 原始观察行]
  O --> F[FieldEvidence 字段证据]
  F --> C[领域对象与候选关联]
  C --> H[人工复核决定]
  H --> P[经审批的公开投影]
  P --> U[查询页面/API]
~~~

| 表/实体 | 不可少的字段 | 所有者与用途 |
|---|---|---|
| Source | source_id、发布方、类别/辖区、页面及原件 URL、使用条件、更新线索、核验时间 | 来源目录，不保存当前推断为永久许可 |
| RawArtifact | artifact_id、source_id、原/最终 URL、UTC 请求时间、HTTP/业务状态、重定向、Retry-After、内容格式、SHA-256、不可覆盖私有路径、批次、发布/截至日 | 采集事实源；失败响应也存 |
| SourceObservation | observation_id、artifact_id、原始 ID（可空）、页/工作表/行定位、原始字段 JSON、观察哈希 | 一份原件可有多条，重复观察不删 |
| FieldEvidence | evidence_id、observation_id、对象/候选 ID、字段名、原值/规范值、适用对象、发布/截至/采集时间、核验状态、前证据 ID | 字段时间线；未知值为 null |
| EntityLinkDecision | link_id、两端对象及关系、候选理由、反证、状态、复核人/时间、所依据证据 | 同名匹配不自动确认 |
| AreaCategoryTask | 地区/类别代码及版本、状态、检索范围、来源集合、覆盖判断、复核时间 | 地区覆盖的分母 |
| PublicationDecision | 来源/字段/批次、用途、授权及隐私依据、语义/时效结论、批准者和时间 | 私有数据进入产品的唯一闸门 |

原始响应/文件、清洗候选、公开投影**物理和权限隔离**。原件带 SHA-256、URL、UTC 时间、批次和行定位；清洗失败、未知列、null、重复、空页仍可复核。派生结果可以重建，原件不能覆盖。字段冲突保留双方，不用空 catch、默认值或“最新优先”吞掉。

## 五、有限采集和复核

开始联网前写明本次 max-pages、max-ids、max-requests、站点、用途和停止条件；先检查 robots、站点声明/数据许可、登录和下载条件。对来源只做有限只读探测。403、429、验证码、登录跳转、身份不符或明确禁采立即阻断该站；保存真实状态与 Retry-After，不使用代理轮换、指纹伪装或绕过。只有许可和样本证据足够，才考虑来源专属解析器；公共能力只抽取确实重复的账本、同站进程互斥、保守间隔、硬预算、不可覆盖原件、SHA 和收据。

解析按原件格式分别验收：HTML 记录表格/链接定位；XLSX/CSV 记录工作表/行号/编码；文字 PDF 记录页码/文本框；扫描 PDF 保存影像、OCR 坐标和置信度，关键字段人工复核。以人工判定的**适用原始行**为抽取率分母，报告可见行、解析成功、拒收原因和最终复核数；不能拿抓到的页数或文件数充当实体数。

请求前预占预算；开始/结束、HTTP/业务状态、耗时、响应身份和预算消耗入账。可恢复网络故障仅在上限内重试；429 按 Retry-After 冷却且停批次。恢复时先离线校验原件、sidecar、SHA 和逐行收据，只有完整者可跳过；损坏/半份详情阻断并审查，不自动重抓。不同来源同名只入待核队列。

## 六、公开产品、运营和验收

首版页面围绕用户任务：全国或适用范围首页、地区/类别检索、对象档案、字段证据和来源页、覆盖/方法说明、纠错入口。档案把官方原文、商业目录和主体自报分组；未核资料不可显示成官方事实。每字段显示来源、适用对象、发布/截至日期、采集时间、核验状态和冲突；“未找到”不写“无证/不存在”。没有证据的评分、价格、实时状态和交易能力不造出来。

公开前逐项过闸：①来源访问/再利用权利；②原件及行定位完整；③对象和字段语义正确，冲突/旧值处理；④个人信息合法性、必要性和展示范围；⑤日期、撤回/更正渠道与更新责任；⑥发布域名/权限/监控和可回滚批次。任一项未知都不能标“通过”，可以继续私有研究。公开投影只含获批字段；个人联系人、电话、敏感资料单独审查。

覆盖报告分别给文件数、来源行数、来源内 ID 数、证件数、候选实体数、人工确认实体数、场所数、字段覆盖率、来源时效和地区×类别缺口。不得把“本轮未发现”写成“没有”；分母、去重规则、适用日期随图表展示。上线后按来源实际发布规律复核，记录链接失效、结构变化、撤回、更正、冲突和重新审批；重大变化暂停相关投影，不用旧数据静默兜底。

试点验收至少做到：每个试点来源有原件 URL/哈希/发布时间/至少一条样本定位；请求、原始行、候选与确认实体分列；100% 对外字段可回原件或授权自报；0 个未经批准的来源/个人字段；失败恢复和回滚演练有收据。成本按来源研究人天、适配器/复核人天、授权/数据费用、扫描 OCR、存储/运维分项估算；在样本与权利未知时只给条件化区间，不报全国全量价格。

## 七、每次新方向的交付顺序

1. 用[模板](source-platform-templates.md)填输入卡，明确用户、对象、地区、用途与假设。
2. 画对象/主张图，列出“可证明/不可证明”，再定地区×类别矩阵及分母。
3. 交来源清单和实际打开的样本证据，四项可行性分别判定；候选与已核验分开。
4. 比较“权威来源优先”“商业目录铺量后逐项核证”“细分地区/类别试点”三路，以字段深度、权利、更新、成本、上线速度选一条。没有来源证据时只推荐待核路径。
5. 交数据模型、来源适配器/账本/恢复方案、公开投影与页面任务；列成本、阶段交付及量化上线闸门。
6. 另请独立审计员抽检 URL、发布方、日期、样本、权利、分母、对象关联；问题按“阻止上线／试点前修复／后续优化”记录。研究方案获确认并且来源权利清楚后，才实施小规模采集或开发。

**新方向启动指令（可复制）：**“按《跨行业信源平台工作系统》为【领域】设计【内部研究／公开查询／商用 API】的信源平台。目标用户是【角色】，需要判断【具体主张】，地域为【范围】，希望在【时限／预算】内做到【最小可用结果】。先填统一输入卡与对象／主张图，再调查具体原件和地区×类别缺口；来源的查询、原件、自动获取、再利用和更新能力分别给证据。先交方案与需核项，不自行推断覆盖率或启动批量采集。”

每次输出一份带日期的任务包：输入卡、区划版本、对象图、来源账本、调查矩阵、采集裁决、试点路线、成本与验收、独立抽检记录。新的领域只继承本协议和可验证的公共能力；具体来源、数据、授权、字段口径和覆盖结论从空白开始。

项目实例：[教培全国独立审计](../research/2026-11-24-national-source-independent-audit.md)只作为对照；[本轮具体数据源核查](source-platform-claim-check-2026-11-24.md)记录区划、企业信用及教培入口的验证边界，**都不是通用许可定义或可迁移统计**。以后新方向用本手册新建对象和来源账本，不继承广东、龙岩、济南的覆盖结论。
