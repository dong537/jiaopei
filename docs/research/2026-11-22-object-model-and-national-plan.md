## 1. 对象模型与不可混淆口径

### 1.1 对象总览

| 对象 | 英文名 | 一句话定义 | 关键判别 |
|---|---|---|---|
| 品牌 | Brand | 面向市场的对外称谓，可跨多主体、多校区存在 | 不是法律主体，无信用代码/许可证号 |
| 登记主体 | LegalEntity | 在市场监督/民政/编办登记的法律实体 | 以统一社会信用代码为准，52 开头为民办非企业单位、91 开头为企业、12 为事业等 |
| 获许可培训机构 | Institution | 持有有效办学许可、可对外开展培训的机构 | 必须有许可证号 + 发证机关 + 有效期的证据 |
| 校区/教学点 | Campus | 一个登记主体/机构名下的具体办学场所 | 一个主体可有多个校区，每个校区单独许可或备案 |
| 办学许可 | License | 教育/人社等部门核发的办学资质证明 | 许可证号 ≠ 登记主体；证有属地码、有效期、年检状态 |
| 课程 | Course | 对外招生的具体培训项目 | 经营范围含「教育咨询」≠ 有课程许可 |
| 官方名单行 | OfficialListRow | 官方名单中刊载的一行原始观察 | 是「收录观察」，不是今日有效性证明 |
| 来源原件 | SourceRecord | 一次请求/下载得到的不可变原始文件或响应 | 带 SHA-256、URL、请求/发布时间、行政区、批次、行定位 |
| 字段证据 | FieldEvidence | 某对象某字段的原始值 + 来源 + 采集时间 + 核验状态 | 逐字段留痕，旧值不删除 |

### 1.2 各对象字段定义

**Brand（品牌）**
- `brand_id`（主键，内部生成）
- `brand_name`：对外品牌名（原始值）
- `brand_name_norm`：规范化名（NFKC + 去标点空白）
- `alias[]`：曾用名/别名
- 关系：Brand 1—N LegalEntity（一个品牌可授权多个主体）；Brand 1—N Campus

**LegalEntity（登记主体）**
- `entity_id`（主键，内部生成，**不得用信用代码当业务主键**，因为跨批次会重复、需留合并审计）
- `uscc`：统一社会信用代码（18 位，原始值；校验位只做形状判断，不做官方核验时标 `unverified`）
- `legal_name`：登记名称（原始值）
- `legal_name_norm`：规范化名
- `entity_type`：`enterprise` / `private_non_enterprise`（民非，52 开头）/ `public_institution`（事业，12 开头）/ `other`
- `registration_authority`：登记机关（市场监管/民政/编办）
- `reg_status`：存续状态（原始值，如「存续/注销/吊销」）
- `reg_address`：登记住所
- `listed_scope`：经营范围/业务范围原文
- `contact_*`（法定代表人、电话、邮箱）：**单独审查，不进公开投影**（见 5.7）
- 关系：LegalEntity 1—N Campus；LegalEntity 0—N License；LegalEntity 0—1 或 1—N Brand（授权关系，需人工确认）

**Institution（获许可培训机构）**
- `institution_id`（主键）
- `institution_name`：机构名（与登记名可不同）
- `license_id`：关联办学许可
- `entity_id`：关联登记主体（**可为空**，民非未入工商库时为空；不能为空就硬配）
- `category`：机构类别（见 1.3）
- `admin_level`：发证层级（省级/地级/县区）
- `region_code`：行政区划代码
- `status`：`listed`（在册）/ `licensed`（已核许可有效）/ `annual_checked`（年检合格）/ `suspended`（停办）/ `expired`（许可过期）/ `unknown`
- **关键：status 只能由证据升级，不能由「未匹配」推断为「无证」。**

**Campus（校区/教学点）**
- `campus_id`（主键）
- `entity_id` / `institution_id`：归属
- `campus_name`：教学点名
- `address`：办学地址
- `region_code`：所在区县
- `license_id`：该教学点的许可/备案（可空，若为「一证多点」需关联主证）
- 关系：Institution 1—N Campus；一个校区只能属于一个机构（教学点不得跨主体）

**License（办学许可）**
- `license_id`（主键，内部）
- `license_no`：许可证号（原始值；号码内含属地码，见 1.5 自检）
- `issuer`：发证机关
- `issue_date` / `valid_from` / `valid_to`：发证与有效期
- `license_type`：`school_training`（校外培训）/ `vocational`（职业技能）/ `driving`（驾培）/ `adult_edu`（继续教育）/ `other`
- `permitted_scope`：核定办学内容原文（**不是课程清单**）
- `annual_check`：年检结论（`pass` / `fail` / `null`）
- `status`：`valid` / `expired` / `revoked` / `suspended` / `unknown`
- 关系：License N—1 Institution（一证一机构；但历史证可换发，需 `license_id` 与历史证分离）；License 1—N Campus（一证多点时）

**Course（课程）**
- `course_id`（主键）
- `course_name`
- `course_type`：学科/艺术/体育/科技/语言/职业技能/驾驶…
- `price`（若官方公布才记录，否则 null，**不得从名单推断价格**）
- `institution_id` / `campus_id`：开设方
- 关系：Institution 1—N Course；Course 独立于许可，一个许可范围内可有多门课

**OfficialListRow（官方名单行）**
- `source_record_id`（主键）：`来源ID:工作表/表位置:行号`，如 `longyan-2026-white-nonsubject:Sheet1:12`
- `source_id`：所属来源
- `row_number` / `table_index` / `sheet`：行定位
- `raw_cells[]` / `raw_fields{}`：原始单元格与字段（保留 null 与未知列）
- `parsed_name` / `parsed_license_no` / `parsed_uscc` / `parsed_address` / `parsed_scope`：解析投影
- `as_of` / `published_at`：名单截至日期、发布日期
- `anomalies[]`：重复许可证号、字段错位、属地码不符等
- 关系：一行 = 一次收录观察；**同名的不同行不合并，同一许可证号出现在多行时全部保留并标异常。**

**SourceRecord（来源原件）**
- `source_record_id`（主键，一次请求的 attempt 或一次导入的文件）
- `source_id`：来源定义
- `url`：准确原件 URL
- `http_status` / `redirect_chain`：真实状态与重定向
- `fetched_at_utc` / `published_at`：请求时间、发布时间
- `sha256`：内容哈希
- `content_type` / `format`：html / xlsx / xls / csv / pdf_text / pdf_scan / image
- `region_code` / `admin_level`：行政区与层级
- `raw_path`：不可覆盖存储位置
- `row_count` / `license_count` / `entity_count`：三个计数**分别**保存，不得混称

**FieldEvidence（字段证据）**
- `evidence_id`（主键）
- `object_type` / `object_id`：适用对象
- `field_name`：字段名
- `raw_value`：原始值
- `source_record_id`：来源
- `captured_at_utc`：采集时间
- `status`：`raw`（原始）/ `verified`（已核）/ `conflict`（冲突）
- `prior_value`：旧值留痕（更新时写，不覆盖）

### 1.3 机构类别（分类，明确排除项）

| 类别 | 主管/发证 | 说明 |
|---|---|---|
| 中小学生校外培训 | 教育部门（学科类）、体育/文化/科技部门（非学科类） | 面向义务教育阶段与高中 |
| 职业技能培训 | 人社部门 | 民办职业培训学校，另有许可 |
| 继续教育教学点 | 教育部门（高校） | 高校学历继续教育校外教学点，非独立办学主体 |
| 驾驶培训 | 交通运输/公安 | 驾培机构 |
| 早教托育/托管 | 卫健/民政/市监 | 托育机构、课后托管，多非「培训」 |

**不可混淆红线：**
- 「学校」≠「培训机构」：公办/民办中小学、中职、高校是学校，不属校外培训机构；名单里「XX学校」需判其是学历学校还是培训学校。
- 「经营范围含教育咨询」≠「获许可机构」：经营范围/业务范围里的「教育咨询、教育信息咨询、文化交流」等字样**不是**办学许可，不能据此标注为持证。
- 黑白灰名单要分开：黑名单/灰名单是「问题机构」，不是获许可机构，不得进入「已核许可」计数。

### 1.4 关系与名称变更

- **一对多**：Brand → LegalEntity；Institution → Campus；License → Campus（一证多点）。
- **多对多**：Brand ↔ LegalEntity（授权）；Institution ↔ Course（一机构多课、一课可多校区）。
- **名称变更**：登记主体更名、机构换牌、品牌改称，需 `FieldEvidence` 记录 `prior_value`，并在 `LegalEntity`/`Institution` 上保留 `alias[]`。**名称一致 ≠ 同一机构**：跨城市同名连锁（如「童画」「神墨」）必须靠信用代码或属地码再判，不能靠名称直接合并（见 1.5 与 5.5）。

### 1.5 许可证号属地自检（本项目已实现，列为通用标准）

- 办学许可证号第 2–5 位为地级市行政区划码（如 4419=东莞、4401=广州）。
- 号码属地码与名单发布地不符 → 判定该行「号码与机构非同一条记录」，进复核队列，**不落匹配**。
- 属地码不成词（如第三位应为 4 却为 2）→ 原件抄写错误，挂起。
- 此自检免费、可复核，是「宁漏配不错配」的第一道防线。

## 2. 行政区划层级（权威来源与版本）

### 2.1 权威来源

- **数据源**：民政部国家地名信息库 — 行政区划代码发布页 `https://dmfw.mca.gov.cn/XzqhVersionPublish.html`。
- **版本**：截至 2025 年末的省、地、县、乡四级行政区划代码（民政部于 2026 年 1 月发布）。
- **依据**：《行政区划代码管理办法》（民政部令第 79 号，2025-09-01 施行）第十六条：国务院民政部门每年 1 月发布截至上一年度末的代码信息。
- **本方案版本日期**：2025-12-31（行政区划口径）；调研过程中任何区划调整须回到该库核对新版本。

### 2.2 层级处理规则

| 情形 | 规则 |
|---|---|
| 直辖市（京/津/沪/渝） | 省级下为市辖区（中间两位 01）与县（02）；区下为乡镇街道。不设「地级」层。 |
| 自治州（如延边、恩施、湘西） | 省下为自治州（地级层），州下为县级市/县。自治州不是地级市，但同为地级行政区。 |
| 地区（如大兴安岭、阿里） | 地区是省级派出机构，无人大政府，但其辖县按地级行政区处理，代码占中间两位。 |
| 盟（如锡林郭勒、兴安） | 内蒙古的盟，地级行政区层。 |
| 不设区的地级市（东莞、中山、儋州、嘉峪关等） | 无「区县」中间层，直辖乡镇街道；调研时「地级=县区」合并处理，不虚构区县。 |
| 省直辖县级（如济源、仙桃、潜江、天门、石河子） | 县级行政区由省直辖，代码中间两位 90。 |

**纪律：**
- 每个来源必须落到**能定位的最小行政层**：县级（6 位码）；不设区地级市落到该市本级（4 位码 + 乡镇）。
- 不得用省级名单推断「各市、各县均已覆盖」；省级名单只证到省级，市/县覆盖必须逐层核到原件。
- 行政区划代码与版本日期随来源一起存档。

## 3. 现有项目数据链审计与风险清单

### 3.1 两条既有链路（现状，待复核）

**链路 A — Next.js `/gd` 公开页面**
- `data/gd.db`（163,776 行企查查投影）→ `src/lib/gd/*` → `/gd`、`/gd/[city]`、`/gd/[city]/[category]`、`/gd/license`、`/gd/org/[id]`。
- `data/whitelist.db`（`wl_rows` / `wl_match` / `wl_review`）→ `/gd/license` 与机构详情页展示许可证号。
- 公开字段含：机构名、地址、类别、许可证号（来源+截至日期+匹配方式）、信用代码投影。

**链路 B — `collector/` Python 包（私有研究，离线）**
- `var/ledger.sqlite3`（runs/attempts/events 账本）、`var/raw/`（不可覆盖原件+SHA-256）、`var/receipts/`、`var/exports/`（`publishable=false`）。
- `var/qcc.sqlite3` + `var/qcc_receipts/`（企查查私有导入，43 份 XLSX / 306,383 观察行）。
- 来源适配器：`longyan.py`（XLSX）、`jinan.py`（HTML）；网络只 `fetch-list` / `fetch-jinan` 各一单。

### 3.2 审计发现（独立结论，分三级）

**A. 阻止上线（Block）**

1. **公开投影的授权未闭环。** `/gd` 页面读的 `data/gd.db` 是企查查数据投影，而 `collector/IMPORTS.md` 与 `2026-11-22-qcc-training-import-results.md` 明确：「企查查文件声明限制向第三方出售及境外传输存储使用」「现有页面的企查查数据公开再利用、手机号等字段展示…仍需单独核验」。即：**公开页面在用一批尚未确认可公开再利用的数据**。证据：`collector/IMPORTS.md` 末段；`docs/research/2026-11-22-qcc-training-import-results.md` 末段。→ 上线前必须确认企查查条款或替换为授权数据源。
2. **同一信用代码跨两条链重复，却未做同一性合并审计。** `2026-11-22-qcc-training-import-results.md`：现有 `data/gd.db` 中 163,398 条非空信用代码能在新批次私有导入中找到相同代码，`training_orgs` 行数同为 167,248。「不能因本次导入验收通过就认定公开展示已获授权」——两套库并行，谁是权威、如何去重、哪个进公开投影，尚无统一决策记录。
3. **民非主体缺口导致「未匹配」可能被误读。** 白名单 2,212 行中 757 行未匹配，多数是民办非企业单位（52 开头信用代码），工商库（91 开头）天然查不到。虽然页面文案已写明「未匹配≠无证」，但 `license.ts` 的覆盖率统计分母是「工商名录核心教培数」，若外部以「覆盖率/合规率」口径引用，会系统性低估民非持证机构。需在数据字典层强制「未匹配」字段语义为 `not_in_business_registry`，而非 `unlicensed`。

**B. 试点前修复（Fix before pilot）**

4. **`/gd` 页面与 collector 是两套对象模型，未对齐。** `/gd` 用 `orgs`（工商主体）+ `wl_rows`（名单行）+ `wl_match`（关联）；collector 用 `SourceRecord` + 名单行 + 候选关联。前者缺 Brand/Campus/Course/License 独立实体，把「名单行」直接当「机构资质」。需以第 1 章对象模型为单一事实源，两链统一映射。
5. **名称匹配只认「完全一致/规范化一致」，但「规范化一致」跨城市有错配风险。** `build.mjs` 的 `byNorm` 是按规范化名全局建 Map，未加「同城市」约束；`normName` 去掉了括号（含城市/行政区前缀），连锁品牌跨市同名会被错配。证据：`scripts/whitelist/build.mjs` 第 130–137 行、第 188 行。虽有三道闸门兜底（信用代码/属地码），但纯名称规范化命中仍建议补「同行政区」约束。
6. **`build.mjs` 直接 `rmSync` 重建 `whitelist.db`，无历史版本留痕。** 证据：`build.mjs` 第 62–68 行。名单行是发布时观察，重建会丢失「某行在上一版本存在、本版本消失」的增量信号（停办/更名线索）。应改为追加式或保留上一版本快照。
7. **OCR 依赖缺失导致扫描件来源记为 0 行。** 汕尾（图片）、英德（扫描件）、省体育局 2,861 家（扫描件）均因无文字层记为 0 行；这些在 `parse-report.json` 标 `needs_ocr`，但 `/gd/license` 页面把「0 行」与「未找到来源」可能混显。需在页面把「来源存在但需 OCR」单列，不并入「已解析行数」。

**C. 后续优化（Optimize later）**

8. **有效期与年检结论未入库。** 东莞年检表、始兴年检表、中山审批表带结论/有效期，当前只取号码，无法回答「这家现在还持证吗」。许可证 `status` 字段已定义但未填充。
9. **单家审批公告（深圳各区、佛山南海/顺德「新增 N 所」）属高频小批量来源，需单独增量策略**，当前未接入。
10. **robots.txt / 条款核验未逐来源归档。** 现有来源注册表（`sources.mjs`）只有 URL/发布单位/截至日期/格式，缺 robots.txt 结论、条款结论、四个独立结论（见 4.4）。需补齐后方可作为持续采集依据。

### 3.3 风险清单（汇总）

| # | 风险 | 等级 | 位置 |

## 4. 分省调研模板与证据标准

### 4.1 逐来源必填字段（一个来源一行）

对每个具体来源（**不是每个省一条**，而是每份可核验的名单/附件一条），输出：

1. `region_code`（6 位县区码或 4 位地级码）+ `admin_level`（省/地/县区）
2. `category`（A 教育校外 / B 体育文化科技 / C 人社技能 / D 继续教育教学点 / E 民政·信用·商业目录）
3. `page_title`（页面标题原文）
4. `url`（准确原件 URL，附件给附件 URL，不是列表页）
5. `publisher`（发布单位）
6. `published_at`（发布日期）
7. `as_of`（名单截至日期；未标注则如实写「未标注」，**不推断**）
8. `format`（html / xlsx / xls / csv / pdf_text / pdf_scan / image）
9. `fields[]`（逐家字段：机构名、许可证号、信用代码、地址、办学内容、年检结论、有效期…逐一列出有无）
10. `sample_row`（样本行定位：表位置/行号/单元格 + 样本值）
11. `visible_rows`（可见行数，**不是**许可证数、机构数）
12. `update_method`（更新方式：公告/年检/动态名单，若不明写「不明」）
13. `login_required`（是否登录）
14. `robots_verdict`（robots.txt 结论：允许/禁止/404/未声明）
15. `tos_verdict`（网站条款结论：可下载/禁止转载/未声明）
16. `web_queryable`（是否可网页查询单家）
17. `batch_feasible`（是否技术上可批量取得）
18. `reuse_allowed`（是否允许再利用）
19. `parse_difficulty`（预计解析难度：低/中/高/需OCR）
20. `verify_time` + `evidence_url`（核验时间与证据链接）

### 4.2 样本核对强制要求

- **实际打开原件并核对至少一条样本行**；打不开、需登录、验证码、403、429、附件失效、条款不明，**如实标记**，不以搜索摘要推定可用。
- 记录真实 HTTP 状态、重定向、Retry-After、响应格式。
- 无许可证号的官方名单仍记为「在册名单证据」，**不得标作许可证证据**。

### 4.3 计数纪律（不得混称）

| 概念 | 独立计数 |
|---|---|
| 页面数 | ≠ 名单行数 |
| 名单行数 | ≠ 不同许可证号数 |
| 不同许可证号数 | ≠ 已确认机构数 |
| 已确认机构数 | ≠ 已核许可有效数 |
| 文件数 | 与机构、许可证分别计 |

同一文件、同一机构、同一许可证号分别计数；跨来源去重必须显式说明去重键（信用代码 / 许可证号 / 名称+行政区）。

### 4.4 每个来源四个独立结论

对每个来源给出**四个互不混同**的结论：

1. **公众能否查询单家机构**（能/不能/需登录/仅列表）
2. **是否有可解析公开原件**（HTML/CSV/XLS/XLSX/PDF 文字层）
3. **是否允许按拟定频率自动获取及再利用**（允许/禁止/未声明/需授权）
4. **是否具备稳定原始行 ID、发布日期、更新线索**（有/无/部分）

### 4.5 来源分类（五类，落为每行状态）

- `首批试点可采集`（有可解析原件 + 可批量 + 字段深 + 允许再利用）
- `仅能人工查询`
- `需授权`
- `技术受阻`（403/429/验证码/扫描件/加密）
- `证据不足`

遇 403、429、验证码或明确限制**立即停止该来源**；不提出代理轮换、伪装指纹、破解验证码、绕过登录。优先找公开附件、开放数据、授权渠道。

## 5. 采集器架构（方案，不实现）

### 5.1 核心实体与状态

沿用第 1 章对象模型，采集器落库三张主表 + 证据表：

```
Source（来源定义）
  source_id PK, category, publisher, region_code, admin_level,

  robots_verdict, tos_verdict,
  reuse_verdict(允许/禁止/未声明/需授权),

  status(active/blocked/retired/unknown)

SourceRecord（来源原件，一次请求/导入）
  source_record_id PK, source_id FK, url,
  http_status, redirect_chain, retry_after,
  fetched_at_utc, published_at,
  sha256, content_type, format, raw_path,
  region_code, admin_level, batch_id,
  row_count, license_count, entity_count  -- 三个独立计数

OfficialListRow（名单行，第 1.4 已定义）
  source_record_id PK, source_id FK, source_record FK,

  raw_cells, raw_fields, anomalies,
  parsed_name, parsed_license_no, parsed_uscc, parsed_address, parsed_scope,
  as_of, published_at

LegalEntity / Institution / Campus / License / Course（第 1.2 已定义字段）
FieldEvidence（逐字段原始值 + 来源 + 采集时间 + 核验状态 + prior_value）
```

### 5.2 原始文件/响应不可覆盖存储

- 每个 `SourceRecord` 的字节以 `attempt_id` 命名，`xb`（排他写）+ `fsync`，同 `collector/store.py` 现有实现。
- 保存 SHA-256、URL、请求时间、发布时间、行政区、批次、行定位。
- HTTP 失败响应也保留；损坏原件标 `quarantine`，不默默重抓。

### 5.3 请求账本、同站互斥、硬预算、阻断与断点恢复

- **账本**：runs / attempts / events，请求发出前占预算，异常退出留 `started`，恢复前离线 reconcile。
- **同站互斥**：每 host 一把进程锁，覆盖探测/列表/详情全部网络步骤。
- **保守间隔**：每来源独立配置，默认 30 秒操作值（非站点承诺）。
- **硬预算**：每次运行显式 `--max-pages --max-ids --max-requests`；`--max-requests` 含失败尝试。
- **阻断**：403、429（存 Retry-After）、验证码、身份不符、重定向到登录 → 停止该来源，不绕过。
- **有限重试**：仅网络超时 / 502 / 503 / 504，在预算内，任何尝试都计数。
- **断点恢复**：`inspect` → `verify` → 离线 reconcile；仅完整收据（原件 + sidecar + 哈希一致）可跳过/续用。

### 5.4 来源专属解析与抽取率验收

| 格式 | 解析器 | 验收 |
|---|---|---|
| HTML 表格 | BeautifulSoup（jinan.py 模式） | 表头不变 + 行数可复算 |
| XLSX/XLS | openpyxl / xlrd（longyan.py 模式） | 文件身份 + 表头 + 行定位稳定 |
| CSV | 标准库 csv（有真实来源再写，不预造） | 编码探测 + 分隔符 |
| 文字 PDF | PyMuPDF `find_tables` + `get_textbox` 按阅读序 | 单元格字序正确（已修复折行打乱） |
| 扫描 PDF/图片 | OCR（tesseract），先装引擎 | 抽取率阈值 + 人工抽验 |

**抽取率验收**：每个来源记录「原件可见行数 vs 解析出行数」，抽取率 < 100% 必须列明漏因（跨页、折行、扫描件），不得把解析失败来源算作完整覆盖。

### 5.5 人工复核队列（`wl_review` 已有，扩展）

以下情况一律进复核队列，自动匹配**只产生候选**：
- 名称变更（新名旧名）；同名不同主体（跨城市连锁）；不同校区（同机构多校区）。
- 许可证重复（同号多行）；停办（名单消失）；来源冲突（两份名单对同一机构结论矛盾）。
- 名称命中与信用代码命中指向不同主体（`name_vs_credit_conflict`）。
- 属地码与名单发布地不符 / 属地码不成词。

**公开「已确认关联」必须有足够证据（信用代码一致、或名称+属地+发证机关多重一致）及复核记录。**

### 5.6 三层隔离 + 个人联系方式审查

| 层 | 内容 | 位置 | 公开性 |
|---|---|---|---|
| 私有原件 | 原始响应/文件 + 收据 | `collector/var/raw`, `var/receipts` | 绝不公开 |
| 清洗候选 | 解析行 + 候选关联 | `var/exports`, `var/qcc.sqlite3` | `publishable=false` |
| 可公开投影 | 经授权核验的机构/许可/名单行 | 网站数据层 | 仅授权字段 |

个人联系方式（法定代表人、电话、邮箱、手机）**单独审查**，不进公开投影。企查查原始 XLSX 含手机/邮箱/法人/地址，公开前必须另做授权与隐私判断。

## 6. 试点选择、成本、风险与验收标准

### 6.1 首批试点地区选择（以真实来源字段深度为依据，不预设省份）

按「字段深度（有无许可证号/信用代码）+ 许可状态可核（年检/有效期）+ 可持续更新 + 使用条件（可下载/可再利用/robots）」四维排序，**当前已核验且字段深**的是：

1. **广东·茂名**（茂南/信宜/高州/化州/电白/滨海，xlsx/xls，含许可证号+信用代码，截至 2026-07-13）——字段最全、格式最规范、可批量，作为第一批试点。
2. **广东·东莞**（全市年检 PDF 54 页 1,261 行，含许可证号+年检结论）——量大、带结论，但 PDF 解析难度中。
3. **福建·龙岩**（非学科 XLSX，机构名+地址+类别，无许可证号）——格式规范但字段浅，仅「在册」证据。
4. **山东·济南高新区**（HTML，含许可证号+办学内容，截至 2026-10-29）——字段中，可作华东样本。

**这些是「小样本采集条件已具备」的候选，不等于全国覆盖。** 其余地区/类别仍是候选或未知（见矩阵文档）。

### 6.2 更新频率与失败恢复

- 白名单/证照齐全名单：按发布节奏（多为年度/半年度），**低频**，单份文件请求。
- 单家审批公告（深圳/佛山）：高频小批量，需独立增量策略，暂缓。
- 年检结果：年度，一年一次。
- 失败恢复：403/429 停来源 → 人工查条款 → 授权渠道；网络瞬时故障走有限重试；断点恢复靠完整收据。

### 6.3 成本与人力估算（量级，非承诺）

| 项 | 估算 |
|---|---|
| 分省来源调研（逐省逐县） | 每省 1–3 人日，31 省约 30–90 人日 |

### 6.4 可量化验收标准

| 指标 | 定义 | 通过线 |
