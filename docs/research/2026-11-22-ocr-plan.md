# OCR 部署与解析器设计（2026-11-22）

> 目标：解锁 whitelist 中 3 个扫描件/图片来源（汕尾图片版、英德扫描件、省体育局 2,861 家扫描件）的许可证号抽取。
> 本阶段**只做环境检测 + 方案设计**，不擅自执行系统级安装（winget 装 tesseract 需用户确认）。

## 1.1 用户需手动执行的一条命令（沙箱无法代装系统软件）

在**本地 PowerShell/终端**（非本对话沙箱）运行：

```
winget install --id UB-Mannheim.TesseractOCR -e --silent --accept-package-agreements --accept-source-agreements
```

装完后验证（应看到 `chi_sim`）：

```
tesseract --list-langs
```

UB-Mannheim 发行版默认含 `chi_sim`（简体中文）。若 `tesseract` 不在 PATH，需把
`C:\Program Files\Tesseract-OCR` 加入 PATH，或在 `ocr_text.py` 里显式设
`pytesseract.pytesseract.tesseract_cmd = r"C:\Program Files\Tesseract-OCR\tesseract.exe"`。

## 2. 部署步骤（需用户确认后执行）

1. 安装 tesseract 引擎（含简体中文语言包 `chi_sim`）：
   ```
   winget install UB-Mannheim.TesseractOCR
   ```
   安装后确认 `tesseract --list-langs` 含 `chi_sim`（UB-Mannheim 发行版默认带 chi_sim）。
2. 安装 Python 依赖（本机 Python 3.13）：
   ```
   pip install pytesseract Pillow
   ```
3. 配置 `pytesseract.pytesseract.tesseract_cmd` 指向 tesseract.exe（若不在 PATH）。

## 3. OCR 解析器设计（`scripts/whitelist/ocr_text.py`）

流程（沿用现有 `pdf_text.py`/`sheet_text.py` 的「输出 JSON 供 parse.mjs 消费」约定）：

```
输入：扫描 PDF / 图片
  ↓ pymupdf 渲染每页为高分辨率 PNG（300 DPI，放大字号、增强对比）
  ↓ pytesseract 中文 OCR（lang=chi_sim，psm=6 单块文本）
  ↓ 从 OCR 文本中抽 15 位许可证号（复用现有 LICENSE_RE /^(1|2|4)\d{14}$/）
  ↓ 输出 JSON：{ pages, hasTextLayer:false, codesInText, tables:[], ocrConfidence, rawLines[] }
```

## 4. 抽取率验收（OCR 的硬门槛）

- OCR 识别「许可证号」这类数字串准确率不稳定，**必须人工抽验**：
  - 每个扫描件来源，随机抽 N 条（建议 ≥20 条或 20%），人工比对 OCR 结果 vs 原件扫描图。
  - 抽取率 < 阈值（建议许可证号抽取率 ≥ 90% 才进库）时，来源保持 `needs_ocr`，不进 `wl_rows`。
  - 许可证号识别错误 = 错配风险（比不识别危害大），沿用「宁可漏配不错配」。
- OCR 产出先落 `data/whitelist/ocr/`（私有），人工抽验通过后才并入 `rows.jsonl`。

## 5. 三个待 OCR 来源的优先级

| 来源 | 类型 | 预期 | 优先级 |
|---|---|---|---|
| 省体育局 2,861 家（B 类） | 77 页扫描 PDF | 量大，解锁全省体育类 | 高（但体育类非 A 类核心，且 77 页 OCR 成本高） |
| 英德（清远） | 扫描 PDF | 单县白名单 | 中 |
| 汕尾（全市） | 图片版名单 | 全市覆盖 | 中 |

## 6. 结论

- OCR 是**解锁 3 个来源的唯一途径**，但**不能替代人工抽验**，也不能把 OCR 识别率当「已确认」。
- 建议顺序：先装引擎 + 依赖 → 用小样本（英德单县）跑通 `ocr_text.py` 并抽验 → 再上省体育局大件。
- **本阶段不执行 winget 安装**，等用户确认后再装（系统级安装 + 需联网下载语言包）。
