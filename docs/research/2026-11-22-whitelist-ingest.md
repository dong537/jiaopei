# 白名单接入：办学许可证号的来源、解析与匹配（2026-11-22）

本次改动解决的是**可信度缺口**：此前站点只有工商登记字段，没有办学许可证号，而许可证号不在工商数据里，  
只能来自教育部门公布的白名单。本文记录接入了哪些来源、解析出多少行、怎么匹配、还差什么。

## 一、为什么不"顺手补一个字段"

- 办学许可证号是《民办学校办学许可证》上的编号，由属地教育行政部门核发，工商登记里**不存在**这个字段。
- 全国校外教育培训监管与服务综合平台（xwpx.eduyun.cn）有权威全量，但需要登录，且没有公开批量接口。
- 因此只能逐份抓取**地市/区县教育局公开发布的白名单**。这类名单发布单位分散、格式各异（HTML 表格 / PDF 表格 / 扫描件 / 图片），  
  覆盖不均，任何一个数字都必须能对回到一份原件。
- 结论：这个字段的价值上限由**来源覆盖**决定，不是靠算法补出来的。所以本项目的做法是  
  ——接了哪几个地方就写哪几个地方，剩下的明确标「未核验」，绝不用其他来源推测号码。

## 二、接入管线

```
scripts/whitelist/sources.mjs   来源注册表（URL、发布单位、截至日期、格式 html/pdf/xls/xlsx）
scripts/whitelist/probe.mjs     候选体检：能不能打开、有没有号码、能不能解析，只判断不入库
scripts/whitelist/fetch.mjs     顺序抓取，2.5s 间隔，原件 + 收据（URL/时间/SHA-256），失败不绕过
scripts/whitelist/parse.mjs     HTML 表格 / PDF 表格 / Excel → 统一行；无文字层则标 needs_ocr
scripts/whitelist/pdf_text.py   PyMuPDF find_tables() 把 PDF 表格还原成单元格矩阵
scripts/whitelist/sheet_text.py openpyxl / xlrd 读 xlsx / xls
scripts/whitelist/build.mjs     落库 whitelist.db + 与 gd.db 五道闸门匹配 + 号码属地自检
scripts/whitelist.mjs           CLI：fetch / parse / build / all / status
```

`probe.mjs` 是这一轮的关键工具：搜到候选页后先跑一遍，10 秒就能知道"这个名单有没有号码"，  
避免把 9 个惠州 xlsx、9 个肇庆 xlsx 这类没有号码的名单全部下载解析完才发现白做。

产物：

| 文件                                 | 内容                                       | 是否提交          |
| ---------------------------------- | ---------------------------------------- | ------------- |
| `data/whitelist/raw/*`             | 官方原件（HTML/PDF）                           | 否（.gitignore） |
| `data/whitelist/receipts/*.json`   | 每份原件的 URL、抓取时间、HTTP 状态、字节数、SHA-256       | 否             |
| `data/whitelist/ledger.jsonl`      | 抓取账本，追加写                                 | 否             |
| `data/whitelist/rows.jsonl`        | 解析后的行（含来源键、发布单位、截至日期）                    | 否             |
| `data/whitelist/parse-report.json` | 每个来源的解析状态、抽取率、失败原因                       | 否             |
| `data/whitelist.db`                | `wl_rows` / `wl_match` / `wl_review` 三张表 | 否             |

抓取纪律沿用 `collector/README.md` 的口径：单进程、顺序、不重试、不换 UA 硬闯；  
403/429 记录后停止该来源；失败响应也留痕。8 个来源全量重抓一次约 20 秒、8 次请求。

## 四、匹配方法：五道闸门

1. 机构名称与名单原文完全相同 → 采用。
2. 去除全角/空白/括号/标点后相同 → 采用，详情页标注"规范化后一致"。
3. 统一社会信用代码相同**且名称对得上** → 采用（最强，但多数名单不刊载）。
4. 名称指向 A、信用代码指向 B；或只有信用代码对得上而名称不同 → 写入 `wl_review`，不落匹配。
5. **号码自证属地**：办学许可证号第 2~5 位是地级市代码（4401 广州 … 4453 云浮）。  
   区划码不在广东 21 市、或与名单发布地不符 → 写入 `wl_review`，不落匹配。

不做地址相似度、不做简称推断、不把同集团不同校区合并。宁可漏配，不可错配——  
错的许可证号比没有许可证号危害更大。

这三道闸门都在真实数据上拦下过东西：

- **规则 4**：黄埔区 PDF 的信用代码列在个别行错位，按"信用代码优先"会把「私立新东方」的号码  
  挂到「行远教育」头上、「粤德教育」的挂到「森澜教育」头上。
- **规则 5**：东莞年检表里有一条 `244160570000619`，属地码 4416 是河源，机构名却是"东莞市石碣…"，  
  说明这一行的号码与机构不是同一条记录；另有 `224191470000569` 第三位应为 4，属地码不成词，  
  应是原件把一位数字打错。两条都挂起，不显示。
- 自检结果：2,210 条一致、2 条不符，说明抽取整体是干净的，异常是个案而不是系统性错位。

另一个已修复的解析缺陷：PyMuPDF 的 `table.extract()` 在中文折行单元格里会打乱字序  
（"一心武道跆｜拳道"被还原成"心武道跆一｜拳道"），导致名称匹配不上。  
改用 `page.get_textbox(cell_rect)` 按阅读顺序重取单元格文本后，匹配数从 997 升到 1,004。

另外补了两个解析器：`sheet_text.py` 用 openpyxl/xlrd 读 xlsx/xls（茂名、番禺、惠州、肇庆都是 Excel），  
`findLicense` 增加"整格抹掉非数字后正好 15 位才算"的宽松匹配，  
解决部分 PDF 把号码拆成 `14420007000 5229` 的问题；该宽松只作用于单元格，不在整行文本上做。

## 五、页面上的呈现口径

- 机构详情页：有号码时显示绿色许可证号 + 发布单位 + 截至日期 + 原件链接 + 匹配方式；  
  没有时说明"不在已接入的来源中"，并明确**未匹配 ≠ 无证**。
- `/gd/license`：登记来源数、解析出的号码数、已匹配主体数、覆盖地市数；  
  按地市核验覆盖表（分母是本站工商名录里的核心教培数，不是全省机构总数）；  
  白名单明细可按地市/已匹配/未匹配筛选、可按名称或号码搜索。
- 城市页与机构列表：只有核到号码的才显示绿色小徽标，未核验不加负面标记，  
  避免把"我们没覆盖"渲染成"这家有问题"。

## 六、还缺什么（下一步的优先顺序）

1. **覆盖面**：21 个地市已接入 6 个（东莞、茂名、广州、云浮、阳江、韶关）。剩下 15 个地市不是没找，  
   是找到的市级名单都不带号码（见「三之二」）。下一轮应该按区县继续挖，而不是按地市：  
   优先级看本站核心教培数——深圳 10,809、佛山 2,854、惠州 1,474、中山、江门、汕头。
2. **OCR**：汕尾（图片版）、英德与省体育局 2,861 家（扫描件）都需要 OCR；本机未装引擎。  
   装上 tesseract 后这三个来源能直接补上广州/清远/全省体育类的空白。
3. **抽取率**：黄埔区 71%，漏掉的 17 个号码源自 PDF 跨页表格识别不全，需换版面识别策略重跑。
4. **有效期与年检**：东莞年检表带"合格/不合格"、始兴年检表带结论、中山审批表带有效期，  
   目前只取了号码，未把结论/有效期入库。这是下一个值得做的维度——它能回答"这家还持证吗"，  
   而号码只能回答"它曾经持证"。
5. **民办非企业单位**：757 行未匹配里大量主体不在工商库，若要做全，需要另接民政部门的社会组织登记数据。
6. **单家审批公告**：深圳市各区、佛山南海/顺德都按"新增 N 所"逐篇发布，含号码。  
   要做的话需要按站点抓列表页并按时间累积，属"高频小批量"来源，得单独设计增量策略。
